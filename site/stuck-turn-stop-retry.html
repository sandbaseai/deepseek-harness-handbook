Retry means three different things.

Runtime policyllm/retry

Retries one model request automatically; it is not a user replay action.

User continuationFollow-up · branch · new Session

Choose after durable closure and effect reconciliation.

Choose by effect certainty.

  • 01No tool admitted: send a revised follow-up after durable abort.
  • 02Known idempotent result: reconcile by its key, then continue.
  • 03Known committed mutation: tell the Agent; do not repeat it.
  • 04Unknown tool outcome: verify the external system first.
  • 05Ambiguous history: branch at a proven boundary or use a clean Session.
  • 06Cancel fails: preserve Remote, Agent phase, and Host evidence.
A safe Retry cannot mean “send the same text again.”

It needs a durable source Turn, visible replay boundary, side-effect gate, new retry identity, click deduplication, and cold-reload tests.
