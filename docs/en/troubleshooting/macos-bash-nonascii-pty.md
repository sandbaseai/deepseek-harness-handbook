# Fix macOS non-ASCII corruption in persistent Bash

Use this guide when DeepSeek Harness on macOS damages Chinese or other non-ASCII text sent through the persistent `bash` tool, then waits until its command deadline.

Reported signatures include:

```text
echo 中文测试          -> --------
git commit -m '优化下载命名' -> timeout
```

Pure ASCII commands succeed, and commands that generate UTF-8 inside Bash from ASCII escape sequences can also succeed.

## Trace the failure boundary

In rc.7, `tool-bash-persistent`:

1. wraps the complete command with unique start and end markers;
2. quotes the command as one ANSI-C Bash string;
3. sends the complete wrapped line in one terminal request.

`terminal-bash` appends carriage return and calls the terminal provider once. The local subprocess terminal then calls `node-pty.write(data)` synchronously. On macOS, the system Bash 3.2 readline path can corrupt multibyte input written too quickly through a PTY.

If the command or wrapper is damaged, the expected `__DSH_PERSISTENT_BASH_END_*` marker never appears. The tool keeps polling until its own deadline, resets the persistent shell, and reports a timeout. Increasing the timeout does not repair the bytes.

## Prove it before patching

Run a small matrix in a disposable workspace:

| Command shape | Purpose |
|---|---|
| `printf 'ascii-ok\n'` | baseline |
| `printf '中文\n'` typed literally | direct multibyte input |
| `printf '\xe4\xb8\xad\xe6\x96\x87\n'` | ASCII transport, UTF-8 generated by Bash |
| non-ASCII commit message | realistic quoted argument |

Capture the macOS version, architecture, `/bin/bash --version`, DSH version, backend type, exact command bytes, output, and whether the completion marker arrived.

## Safe immediate choices

### Use bounded one-shot shell execution

If the active profile exposes the non-persistent local Bash executor, use it for commands carrying non-ASCII arguments. It launches `bash -c` as an argument instead of typing the command through an interactive readline PTY.

### Keep the transmitted command ASCII

For a small, fully reviewed argument, generate UTF-8 inside Bash from byte escapes. Do not hand-convert arbitrary shell programs or secrets. Incorrect escaping can change quoting and command meaning.

### Use a newer Bash in a custom profile

Point a tested terminal backend at a current Bash installation, then verify prompt readiness, interruption, markers, Unicode round trips, and cleanup. Merely installing newer Bash does not prove the shipped profile uses it.

## Durable repair shape

A narrow source repair can make the ANSI-C quoted command ASCII-only by UTF-8 encoding non-ASCII code points and emitting each byte as `\xHH`. Preserve the existing escaping order for backslash, single quote, carriage return, and newline.

The repair belongs at the command serialization boundary, before the one-shot PTY write. It should not modify output decoding, marker parsing, or arbitrary user files.

## Regression gates

- ASCII commands remain byte-for-byte unchanged.
- CJK, accented Latin, emoji, and mixed scripts round-trip exactly.
- Quotes, backslashes, newlines, and carriage returns retain their meaning.
- Start and end markers are still found.
- Exit status survives non-ASCII arguments.
- Cancellation and timeout still reset only the owning Agent shell.
- Linux behavior and newer Bash paths do not regress.
- No secret appears in debug output.
